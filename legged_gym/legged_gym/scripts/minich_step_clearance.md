# Mini Cheetah 越阶净空与每次摆动后摆奖励

## 当前版本：直行摆动后摆 1.5–3 cm，扣除机身倒退贡献

`StepRetraction` 现在在所有地形的前后直行摆动中工作。
旧版“检测到立面反力后才回收”的触发逻辑已替换。
没有台阶、没有碰壁、足端已经抬高，都不会取消本次后摆要求。

启用条件：`abs(vx_cmd) >= 0.10 m/s` 且 `abs(wz_cmd) < 0.05 rad/s`。
纯侧移、站立、原地旋转及明显转向时不计算本项。
若同时有 vx/vy 命令，则方向取完整目标 XY 速度方向。
速度范围与速度课程保持原配置；本改动没有将速度上限设为 0.5 m/s。

方向为目标速度的反方向。环境命令在机身系表达，先按当前 yaw 转换到
世界坐标。每次摆动锁存这个世界方向 d，后续机身转动不会旋转该次测量轴。
倒退命令下，后摆方向也随之反向。

各脚独立地确认支撑 0.06 s，再确认离地 0.04 s 后开始一次摆动任务。
原点 p0 取第一次离地之前的最后一个控制采样，而不是确认离地之后的采样，
因此离地确认期间已经发生的位移仍计入。初始悬空或重置后未建立支撑历史
不会触发假摆动。接触反力须 >1 N，且足底在水平地形高度的 1.2 cm 内才算
支撑；仅有立面摩擦的竖直反力不能直接当作正常落地。此高度用于训练奖励
的支撑判别，不要求存在台阶，不进入 Actor。

### 位移定义与防整机倒退

锁存的 `d` 是命令的世界前进方向，定义：

- 世界后摆 `s_world = -dot(p_foot_xy - p0, d)`。
- 本次摆动内机身累计反向移动 `B += max(-dot(base_xy - previous_base_xy, d), 0)`。
- 有效后摆 `s_eff = s_world - B`。

`B` 从第一次离地（包括离地确认延迟）开始累计，机身随后前进不会退还这部分扣除量。
因此整机带着足端一起后退时 `s_eff=0`；机身前进、足端相对机身后移但世界仍
向前时也不会计为有效后摆。测量方向在世界系锁存，不随本次摆动中的偏航旋转。
这是对机身逆向平移贡献的扣除，不等同于消除所有姿态旋转造成的足端位移。

下限 `D_min=0.015 m` 用有效后摆判定；上限 `D_max=0.03 m` 用实际世界后摆
判定。这样既不能靠机身倒退满足下限，也不能扣除机身位移后掩盖真实超量后摆。
相对机身与世界位移均属训练奖励信息，不增加 Actor 输入。

### 区间惩罚，关闭正向奖励

配置 `step_retraction=0`，`step_retraction_stall=-0.20`。区间内不发正向奖励。
`progress_reward` 仍保留为兼容诊断缓存，但默认不参与总奖励。

不足惩罚保留 `T=0.30 s` 的进度过渡，避免刚离地就要求瞬间达到 1.5 cm：

`s_ref = D_min * clamp(elapsed / T, 0, 1)`

`lag_cost = clamp((s_ref - s_eff) / D_min, 0, 1)^2`

只在尚未达到下限时计算。无水平支撑时记录 `best=max(best,clamp(s_eff,0,D_min))`；
达到下限后允许正常前摆落地，不会因为前摆把当前后摆距离减小而重新扣不足惩罚。
到 0.40 s 仍不足时标为 TIMED_OUT，继续惩罚并允许迟到完成；抬高不能替代后摆。

整个摆动（包括 COMPLETE 阶段）持续记录无水平支撑时的世界后摆峰值 `world_best`：

`over_cost = clamp((world_best-D_max)/(D_max-D_min),0,1)^2`

超过 3 cm 连续平方惩罚，超出 1.5 cm 时饱和；之后向前摆不会抹掉这次超量记录。
每步实际贡献为 `-0.20 * dt * (lag_cost + over_cost)`，逐脚求和。

### 落地结算

连续水平支撑 0.04 s 后结束本次摆动，追加一次区间外惩罚：

`deficit = clamp(1-best/D_min,0,1)^2`

`landing_cost_raw = (deficit + over_cost) * (0.30/dt)`

实际贡献为 `-0.20 * 0.30 * (deficit+over_cost)`。完全没有有效后摆时每脚一次扣
0.06；超量也有终端结算，避免快速超量后立即落地逃掉惩罚。1.5 cm 和 3 cm 边界
包含在合格区间内。支撑期拖脚不增加有效进展或后摆峰值。

`completed`/COMPLETE 表示曾达到下限，可以进入前摆；不代表整次摆动最终合格。
落地时不足或超量均设置 `failed_landing`。分析应同时看 `best`、`world_best`、
`body_backward` 与落地结果，不能仅统计 `completed`。

停止、转向或输入的 XY 命令方向相对触发时改变超过 60 度会取消旧任务。
机器人自身偏航不会旋转锁存测量轴，也不能靠自身转向清除该次任务。恢复
直行时须重新建立支撑历史，不会在半空中反复重开。reset 清空所有状态。

沿用日志名 `rew_step_retraction` 和 `rew_step_retraction_stall`，后者现在
包含不足、超量与区间外落地代价，不能直接与旧训练中同名停滞值比较。
`started/completed/failed_landing` 是逐脚单步事件缓存，供回放检查。

## 原有越阶净空项

当前 `step_clearance=0`，越阶项已关闭。其原公式以台阶踏面高度 +3 cm 为目标；8 cm 台阶对应足底
11 cm、球心 13 cm（足端球半径 2 cm）。沿目标方向检查前方 15 cm 的第一个
上升边缘，正常支撑不触发，跨过边缘后解除，四脚独立。

净空代价为：

`cost_i = active_i * approach_i * release_i * clamp((target_z - sole_z)/margin, 0, 1)^2`

每脚每步最多扣 `0.25*dt`。后摆阶段 RETRACT 暂缓该脚的净空惩罚，完成
或超时后恢复。后摆任务有自己的生命周期，净空目标解除不会使它提前完成。
即使将 step_clearance 系数置零，后摆奖励也能独立运行。

地形高度是网格近似，不是碰撞网格射线检测。训练默认 10 cm 水平网格，
手工回放楼梯为 2 cm；1 cm 的前向查询间隔不会提高原网格精度。
所有新奖励在 post_physics_step 更新一次，奖励查询只读缓存。
Actor 输入、网络和导出接口保持原样。总奖励原有的正值裁剪仍然生效，
上述负值是奖励项自身的贡献，不保证与最终裁剪后的总奖励差值相等。

本项是训练软约束，不是轨迹执行器。是否每次都实际完成世界系后摆，是否
出现整机倒退或改变步频，需重新训练后按每脚完整摆动轨迹验收。

本版本验证产物：`legged_gym/logs/retraction_band_20261020/`。

这是训练软约束，修正指标不会立即改变旧模型的倒退行为。仍需重训后验收
正向推进、碰阶后恢复、零命令停车与各脚区间达标率；本次不调整速度跟踪系数。

### 高度定义和计算函数

每只脚分别记录一次摆动的最大足底净空：

`H = max_t(foot_world_z - foot_radius - ground_height_at_current_foot_xy)`

单位为米；足端半径为 2 cm，所以平地足底 5–8 cm 对应足端中心 7–10 cm。
这里只采样脚下地面以计算训练指标，没有“前方出现台阶”触发条件。

函数 `peak_height_score(H)`，令 `u=(H-0.05)/0.03`：

- H < 0.05：`-clip((0.05-H)/0.05, 0, 1)^2`。
- 0.05 ≤ H ≤ 0.08：`4*u*(1-u)`。
- H > 0.08：`-clip((H-0.08)/0.03, 0, 1)^2`。

| 峰值足底高度 | 原始分数 |
|---|---:|
| 0 cm | -1 |
| 2.5 cm | -0.25 |
| 5 cm | 0 |
| 5.75 cm | +0.75 |
| 6.5 cm | +1 |
| 7.25 cm | +0.75 |
| 8 cm | 0 |
| 9.5 cm | -0.25 |
| ≥11 cm | -1 |

函数值连续，5 cm 和 8 cm 边界为零，6.5 cm 是区间中心最优点，奖励不是
持续增加到 8 cm 再突然跳成负值；分段连接处不要求导数连续。

### 事件结算与防重复计分

各脚稳定支撑 0.06 s 后才准备下一次摆动，初始悬空不会创建事件。离地开始
记录峰值，连续落地 0.04 s 后结算一次，支撑期间不记录峰值。离地不足 0.08 s
的短促接触丢失不能拿正分（不足或超量仍可扣分）。摆动满 0.50 s 还未落地时
结算一次 -1，随后必须稳定支撑才能重新开始，不会一直悬空持续领分。
停止、转向、命令反向时取消旧事件，reset 清空动作状态。

原始 reward accessor 返回 `sum(逐脚事件分数)/dt`；环境的奖励系数再乘 dt，
所以系数 0.02 表示每脚每次摆动最多 +0.02、最少 -0.02，与控制周期无关。
原来的总奖励正值裁剪仍存在，负的单项贡献不保证最后的总奖励也为负。
高度事件是软约束，不能单独排除跳跃、异常步频或身体姿态补偿；须结合机身
运动和速度跟踪验收。不要仅根据奖励升高认定所有脚都学会了正常摆动。

### TensorBoard 统计

`Episode/gait_height/<foot>/{count,peak_sum_cm,under,in_band,over,timeout}`
记录各重置批次的逐脚事件计数和峰值累计高度，统计范围只有启用的步态组。
在同一训练迭代，`peak_sum_cm/count` 为事件平均峰值厘米数，`in_band/count`
为高度在区间内的比例；count=0 时不要计算比率。in_band 只表示高度在区间内，
可能包含超时或过短摆动，因此还要检查 timeout。under/over 是事件数量，不是
惩罚的大小。这样避免把事件增多误判为高度表现变差。

训练进程需要重新启动加载配置。所有环境共享同一策略网络，这 20% 的训练会
影响共享策略；不会创建一个只在这些编号上运行的独立策略，也不新增 Actor 输入。
验证产物：`legged_gym/logs/gait_peak_height_20261020/`。

## 两项奖励的逐脚诊断日志（2026-10-20 补充）

前 20% 环境在命令采样时将 vy/wz 清零；每次命令更新后再次强制 vy=0。
其他环境的侧移命令不受影响。这里限制的是目标命令，不保证机器人实际侧移为零。

优先查看 TensorBoard 的 `Gait/` 标签；HIM runner 按每次训练迭代内收到的
重置统计先求和、再做除法，避免小样本批次的达标率与大样本批次等权平均。
只有有已结束 episode 的统计时才输出；没有对应事件时不填假零均值或假零达标率。
原 `Episode/gait_height/...` 原始统计保留，并新增后摆原始统计。

| 标签前缀 | 范围 |
|---|---|
| `Gait/height/<foot>/` | 前 20% 的抬腿高度项 |
| `Gait/retraction/<foot>/` | 前 20% 的后摆项 |
| `Gait/retraction_other/<foot>/` | 其他环境符合门控时的后摆项 |

`<foot>` 为 FL_foot、FR_foot、RL_foot、RR_foot。

高度项重点看：

- `mean_peak_cm`：每次结算的最高足底净空均值，目标 5–8 cm。
- `under_rate`、`in_band_rate`、`over_rate`：按结算事件数归一化的高度分类。
- `valid_landing_rate`：高度在区间内、实际落地、且腾空时长不短于 0.08 s 的比例；
  区别于只检查高度的 in_band_rate。
- `short_rate`、`timeout_per_started`、`cancelled_per_started`：短促摆动、超时与取消。
- `mean_raw_event_score`：含短促摆动和超时规则后的平均事件原始得分。
- `positive_reward_per_enabled_second`、`negative_reward_per_enabled_second`：正负贡献拆分。

后摆项重点看：

- `mean_effective_peak_cm`：扣除累计机身倒退后，摆动期实际有效后摆峰值均值。
  此诊断不使用奖励缓存中封顶为 1.5 cm 的 best，超过下限的实际幅度仍可见。
- `mean_world_peak_cm`：世界后摆峰值均值，检查是否超过 3 cm。
- `mean_body_backward_cm`：每次落地时，本次摆动被扣除的累计机身反向路程。
- `in_band_rate`：落地时下限已达标且没有超过世界上限；under_rate/over_rate
  分别表示不足/超量，二者可能同时发生，不能要求三者相加为 1。
- `timeout_per_started`：曾超时的比例，每个事件只记一次，迟到达标也保留超时记录。
- `lag_reward_per_enabled_second`、`over_reward_per_enabled_second`、
  `landing_reward_per_enabled_second`：不足进度、超量、落地结算三部分负贡献。

两项均有 `count`（高度结算次数/后摆落地次数）、`started`、`cancelled`、
`events_per_enabled_second` 和 `reward_per_enabled_second`。均值和区间比例以
count 为分母，timeout/cancelled 比例以 started 为分母；奖励速率以本项启用时间
为分母。统计按脚分开，四脚贡献之和才是对应环境组的该奖励总贡献。
奖励贡献均已乘配置系数，但在总奖励正值裁剪之前；不能把负贡献当成最终 PPO
总奖励减少量。取消（包括重置打断）的事件不混入落地峰值均值，故须同时看取消率。

日志没有改变奖励公式或 Actor 输入。验证目录：
`legged_gym/logs/gait_metrics_20261020/`，其中 TensorBoard 回读使用合成事件验证
统计链路，不代表策略已经学会这些动作。
