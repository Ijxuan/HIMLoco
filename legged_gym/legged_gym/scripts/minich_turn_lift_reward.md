# Mini Cheetah 最低抬脚训练奖励

在现有 `feet_air_time`（权重1）内实现，不新增奖励名称。MiniChRoughCfg 启用新逻辑；未配置 turn_lift_min_clearance 的其他任务继续使用原腾空时长公式。观测和网络维度不变。

## 默认标准

- 足底相对局部地形高度至少0.01m（含边界），足端球半径0.02m。
- 每足最近4秒至少2次有效抬起并落地，即0.5Hz。
- 原地转动门控：线速度命令模长<0.1m/s，yaw命令绝对值>=0.2rad/s，正负方向相同。
- 有效动作必须在当前连续转动期间开始、达到高度、并落地；转动开始前已悬空或跨越非转动阶段的动作不计有效次数。

## 得分

每足记录最近两次有效落地距今时间（窗口左开右闭）。

1. 有效落地时，若该足窗口内次数尚未达到2次，给予原始奖励+1；窗口内已足够频繁则不继续发放额外落地奖金，但更新时间记录。
2. 每步计算目标次数 `expected = min(连续转动秒数,4) * 0.5`。每足缺额为 `max(expected - 窗口内有效次数,0)/2`，对四足取平均，以系数1连续扣分。这样启动阶段逐步提高要求，短于4秒的转动也有反馈，四足静止到4秒时每步原始缺额惩罚为−1；只有一只脚满足标准时为−0.75。
3. 沿用超过0.30s的连续悬脚惩罚。缺额奖励不再要求腾空时长必须接近0.25s；达到1cm的短抬脚也可得到有效落地奖励。超过0.30s的动作即使达到高度并落地，也仍支付原有超时惩罚。
4. 原始各项相加后仍由环境统一乘 reward scale 和 dt。dt=0.02、scale=1时，一个有效落地奖金为+0.02，完全不抬脚的稳定缺额惩罚为−0.02/控制步。环境原有总奖励非负截断继续生效。

零命令、平移或yaw低于门控时清空频率与抬高记录，不再扣频率缺额。已经激活的悬脚超时惩罚仍按原逻辑持续到落地。episode reset 清除选定环境的计数、峰值、资格、连续转动计时和接触滤波状态。

## 高度定义与边界

使用 `_get_feet_heights()` 返回的足中心相对局部地形高度减去0.02m。平地对应足中心世界高度至少0.03m。高度场/三角网格沿用现有地形栅格采样（附近三个高度的平均），台阶边缘是近似值，不是接触面精确重建；悬脚本身通过接触力滤波判定。

训练中的启动目标采用连续爬升，4秒以后与评估的每足两次窗口要求一致。训练还保留独立悬脚超时惩罚，最低高度/频率达标不等于其他步态评分项达标。窗口内更早的超额事件不必保存，因为一旦最近两次已过期，所有更早事件也必然过期。

## 配置

`legged_gym/envs/minich/minich_config.py`：turn_lift_min_clearance、turn_lift_min_frequency、turn_lift_window_s、turn_lift_foot_radius、turn_lift_frequency_cost。窗口时长乘最低频率必须是正整数。现有 feet_air_time_target/min/max 继续提供旧任务公式及超时成本斜率参数；Mini Cheetah的落地奖金不再使用0.25s三角形时长评分。

2026-10-13，gym4中全部52项测试通过，包含高度1cm边界、正负0.2门控、低抬脚、不抬脚、单足补偿漏洞、奖励次数封顶、窗口过期、悬脚、命令切换、局部地形高度、选择性episode reset和旧任务奖励回归。

CPU PhysX三策略19秒回放通过（3秒站立、+0.25转动10秒、6秒站立）：`legged_gym/logs/turn_lift_reward_smoke_20261013/`。这仅验证新奖励能正常计算，不证明学习效果；需要重新训练或续训并用固定正负转向测试验证策略。
